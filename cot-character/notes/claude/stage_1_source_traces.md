# Stage 1: Source Trace Collection

## High-Level Goal

Assemble a corpus of high-quality, correct reasoning traces that will serve as raw material for style transfer in Stage 2. These traces should contain genuine step-by-step reasoning inside `<think>...</think>` tags followed by a correct final answer. The traces themselves do not need to have any particular "character" — they just need to be logically sound and diverse enough to provide good coverage for style transfer.

Think of this stage as building the "skeleton" of reasoning that Stage 2 will then dress in different emotional/motivational clothing.

## Context

The overall project (see `cot-character/CLAUDE.md` for full details) aims to shape the inner monologue of OLMo-3-32B-base models using constitutionally-defined reasoning styles. The pipeline is: **source traces → style transfer → SFT → RL**. This stage produces the first artifact in that chain.

The parent repo (`geodesic-open-rl`) already uses several datasets for GRPO training — math, code, and general reasoning tasks. These same datasets (or subsets of them) are natural candidates for sourcing traces. The existing warm-start dataset generation pipeline in `warm-start/dataset_generation/` also provides patterns for filtering and quality-scoring traces.

## Interface

### Inputs
- Existing datasets used by the GRPO pipeline (see training configs in `configs/isambard/*.yaml` for `dataset_mixer_list` fields)
- Existing datasets with reasoning traces (e.g. Dolci-Think-SFT, or traces generated by a thinking model on math/code prompts)
- Alternatively: prompts from existing datasets + a thinking model to generate traces from scratch

### Outputs
- `data/source_traces/` containing JSONL files
- Each record should have at minimum:
  - `prompt`: the original user question/problem
  - `reasoning_trace`: the full CoT (content inside `<think>...</think>` tags)
  - `final_answer`: the answer given after `</think>`
  - `domain`: what kind of problem this is (math, code, general, etc.)
  - `source_dataset`: provenance tracking
- Target: enough traces to produce a meaningful SFT dataset per character after style transfer (order of magnitude: 1000+ source traces)

## Checks

- **Structure**: every trace has `<think>...</think>` tags with a clear final answer after the closing tag
- **Correctness**: answers are verified correct using existing verifiers where applicable (math verifier for math problems, code execution for code problems). Traces with incorrect answers should be discarded — we don't want to style-transfer broken reasoning
- **Diversity**: reasonable spread across difficulty levels and domains. Not all easy problems, not all hard problems. Not all from one narrow topic
- **Quality**: manual inspection of ~50 traces to confirm:
  - Reasoning is genuinely step-by-step (not just restating the answer)
  - Traces are coherent and readable
  - No degenerate patterns (e.g. repetitive filler, copy-pasted boilerplate)
  - Reasonable length distribution (not all trivially short or excessively long)

## Key Decisions to Make at This Stage

- **Source strategy**: Do we use existing reasoning traces from a dataset (e.g. Dolci-Think-SFT), or generate fresh traces by running a thinking model on prompts? The former is faster; the latter gives more control over quality and format
- **Domain mix**: What proportion of math vs code vs general reasoning? This should probably match whatever mix the RL stage will use, so the SFT data is in-distribution for RL training
- **Volume**: How many source traces do we need? This depends on how many survive quality filtering and how large we want the per-character SFT datasets to be
